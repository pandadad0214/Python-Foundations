 # Contributing Guide

This document explains how contributions, commits, and project structure are managed in the Python Foundations repository. It ensures consistency, clarity, and a professional development workflow as the project grows.

## Getting Started

1. Fork or clone the repository.
2. Create a dedicated branch for your work.
3. Make focused changes that align with the repository's goals.
4. Run relevant checks before opening a pull request.

## Project Structure

Organize code by topic or learning objective. Keep examples, exercises, and supporting documentation in the appropriate directories, and use clear, descriptive names.

## Commits

- Write concise, imperative commit messages.
- Keep each commit focused on one logical change.
- Avoid committing generated files, secrets, or unrelated formatting changes.

## Pull Requests

Include a clear summary of the change, explain any important implementation decisions, and mention tests or checks performed. Keep pull requests reviewable and respond constructively to feedback.

## Code Quality

Follow existing Python style and documentation conventions. Prefer readable, maintainable solutions and add or update examples and tests when appropriate.

Thank you for contributing to Python Foundations.

- Week 1: Added root README.md
- Week 1: Added Python .gitignore

## Coding Style Guidelines

- Use clear, descriptive variable names.
- Keep functions small and focused.
- Use consistent indentation (4 spaces).
- Add comments to explain non-obvious logic.
- Avoid duplicate code — refactor when needed.
- Keep each script focused on one purpose.

## Repository Structure

All work is organized by week:


week1_basics/
week2_data_structures/
week3_web_data/
week4_databases/
capstone/

Each week contains:
- Python scripts for that week's lessons
- A README.md documenting progress
- Any supporting files or notes
